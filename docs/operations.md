# Эксплуатация учебного стенда

## Конфигурация

`DATABASE_URL` — SQLAlchemy URL; `BASE_URL` — внешний адрес для QR; `ALLOWED_ORIGINS` — точный список Origin через запятую; `COOKIE_SECURE` — true для HTTPS; `FRONTEND_DIST` — путь к сборке интерфейса. `.env` не попадает в Git или Docker context.

Запуск из README создаёт схему v1 автоматически. `init-db` доступна как явная идемпотентная команда. Обновление уже существующей схемы будущих релизов пока не реализовано; перед изменением структуры нужен инструмент миграций и отдельный план отката.

## HTTPS для пилота

Настроить DNS на сервер. В `.env` установить DOMAIN=домен, BASE_URL=https://домен, ALLOWED_ORIGINS=https://домен, COOKIE_SECURE=true, случайный POSTGRES_PASSWORD. Запустить:

```bash
bash scripts/compose.sh --profile https up -d --build
```

Caddy получает сертификат и перенаправляет HTTP на HTTPS. Приложение доступно на loopback, БД не публикует порт наружу. В dev локальный HTTP и COOKIE_SECURE=false допустимы. Проверить вручную cookie Secure/HttpOnly/Lax и редирект. Пилотный HTTPS-домен в ходе разработки не создавался.

Ограничить доступ к хосту, `.env`, Docker socket и резервным копиям. Прокси ограничивает тело запроса 6 MB; endpoint изображения — 5 MiB/12 MP. Для приватности загрузок использовать отдельный tmpfs для /tmp в контейнере: spool исчезает при остановке контейнера. Формальная очистка аварийных файлов по TTL 15 минут отдельно не реализована.

## Резервные копии

```bash
bash scripts/backup.sh
ls -lh backups/
```

Скрипт делает pg_dump custom-format в файл .partial, затем переименовывает, выставляет umask 077 и оставляет 7 последних завершённых копий. Том PostgreSQL не удалять при обычном обновлении. Снимков маркировки в БД нет.

Ежедневный запуск настраивает оператор через планировщик сервера. Автоматизация на пользовательском компьютере не создавалась. Целевой RPO ≤24 ч достигается только при работающем расписании; целевой RTO ≤30 мин нужно измерить на 1000 инспекций на стенде PERF-01. Для защиты от потери хоста копии нужно шифровать и переносить в отдельное защищённое хранилище.

Восстановление заменяет содержимое текущей БД. Сначала проверить копию на отдельном стенде. Явная команда оператора:

```bash
bash scripts/restore.sh backups/medkit-TIMESTAMP.dump
```

Скрипт останавливает приложение, выполняет pg_restore одной транзакцией, запускает приложение и проверяет ready. При ошибке восстановления приложение остаётся остановленным, чтобы не открыть частично восстановленную систему. После восстановления заново проверить историю, роли и PDF.

Проверка восстановления в новую БД без замены рабочей:

```bash
bash scripts/check_backup.sh backups/medkit-TIMESTAMP.dump
```

Скрипт сравнивает число и контрольную сумму снимков COMPLETED. Проверочная БД сохраняется для осмотра; оператор может удалить её после проверки. Для TRACE PostgreSQL доступны `scripts/trace_postgres.py` и режим `--verify` после перезапуска. Они предназначены для искусственных демоданных, не для продуктивного наполнения.

## Релиз и откат

1. Выполнить make check/test/build. Выполнить backup.
2. Установить IMAGE_TAG в хеш текущего коммита, сохранить старый тег/образ и .env.
3. `bash scripts/compose.sh build app`; образ получает OCI-label revision.
4. `bash scripts/compose.sh up -d app`; проверить `/health/ready` и вход/историю.
5. Для отката вернуть прежний IMAGE_TAG и выполнить `bash scripts/compose.sh up -d --no-build app`.

Образы автоматически не публикуются. Для первой версии схема совместима с самим собой; после изменений схемы откат образа может потребовать восстановления backup. Не запускать `down -v`, если нужны данные.

## Наблюдаемость

`/health/live` — процесс, `/health/ready` — доступ к БД и начальной таблице схемы. JSON-события содержат request_id, HTTP code, duration_ms. Uvicorn access-log отключён, тела запросов и изображения не логируются. Логи приложения можно посмотреть через `bash scripts/compose.sh logs app`.

Один worker обязателен: лимиты входа и очередь OCR в памяти процесса. Горизонтальное масштабирование требует общего rate-limit storage и очереди. Текущий лимит Tesseract 12 сек ограничивает распознавание; общий срок с ожиданием/декодированием требует доработки до жёсткого deadline 15 сек из SRS.
